# 秀エクセルマネージャー（開発中のものを、そのまま公開しています）

Excel の VBA マクロ・シート・テーブル・ピボット・グラフ・パワークエリを、**Python 経由で AI が直接さわれるようにする道具**です。
Claude Code や Antigravity（Gemini）に MCP サーバー `excel-manager` として登録すると、開いている Excel ブックに対して、
会話でマクロを直す・作る・表を整える、ができます。

> ⚠️ **研究中の道具です。** 版は 0.x、仕様は予告なく変わります。動作の保証はありません。
> 自分のブックを相手に、家で使っているものを、手元の姿のまま出しています。大事なブックには、必ず控えを取ってから使ってください。

前身の「秀VBAマネージャー」は、2026 年 9 月 5 日の姿のまま残してあります（以後は更新しません）。
https://github.com/shu1551/shu-vba-manager

## 何が出来るようになったか

五月に「会話するだけでマクロが直る」から始めた道具です。四か月のあいだに、AI が実物の Excel の中で
**VBA を入れる・コンパイルする・撃つ・結果を読み戻す・だめなら戻す**、の足場が出来ました。

その足場の上に、2026 年 9 月、次の回路が載りました。

1. 依頼が来たら、登録済みのマクロが先に撃つ（AI は呼ばない・一秒前後）
2. マクロで片付かない仕事だけ、AI がその場でやる
3. AI がやった仕事を、AI 自身がマクロに書く
4. 道具が、**正解の付いたお題**でそのマクロを試す。値だけでなく、型・グラフ・ピボット・テーブル・クエリの姿まで比べる。
   外れは理由を付けて AI に返し、同じ外れが続いたら道具が止める
5. 合格したマクロを登録する。次からは、その仕事もマクロが片付け、AI は呼ばれない

**回した分だけ、AI の要らない仕事が増えていく**形です。一言頼んで、AI が何時間も一人で回り続けられるところまで来ました。

## 入っているもの

| 場所 | 中身 |
|---|---|
| `作業ファイル/project/python_scripts/vba_manager.py` ほか `vbam_*.py` | 道具の本体。コマンドラインからも使えます（`py vba_manager.py list` など） |
| `…/vba_mcp_server.py` | MCP サーバー `excel-manager`。常駐して Excel とつなぎっぱなしにするので、応答は 0.01〜0.2 秒級 |
| `…/vbam_agent.py` `vbam_prefire.py` `vbam_forge.py` `vbam_mend.py` `vbam_exam.py` `vbam_objects.py` ほか | AI エージェントの部分（マクロの先撃ち・鍛える回路・修理の試験・正解つきの試験・グラフやピボットを読む目） |
| `…/form_builder.py` ほか `form_*.py` | UserForm を宣言で組む・検査する |
| `…/test_*.py` | 機械の試験（Excel も AI も使わないものが大半。`py -m pytest -q`） |
| `秀コンボ.xlsm` | **アドイン本体**。VBA だけで動きます（AI も Python も API キーも要りません）。マクロを一覧から選んで撃つフォーム・ショートカットの管理・ワークシートの一覧・プリンタの切り替え・カレンダーなどの道具と、下の「表の整理」のマクロが入っています。開いて「アドインの更新登録」を押すと、アドイン（.xlam）として登録されます |
| `作業ファイル/project/macros/表の整理.bas` | 回路で鍛えて登録したマクロ（表を整える・重複行を消す＋鍛えた仕事）の書き出し。アドインに入っているものと同じです。文字コードは Shift-JIS（CP932） |
| `作業ファイル/project/fixtures/` | **お題の作り手**。鍛える回路で使う、正解つきの表を種の番号から作るスクリプト（仕事ごとのフォルダが 100 あまり）と、依頼文・言い換え。作った表（xlsx）は入れていないので、各フォルダで `py make_pairs.py` を実行すると作れます。回し方（会話している AI が自分でマクロを書く形も）は `fixtures/マクロの鍛え方.md` |
| `.claude/skills/` | Claude Code 用の手順書（スキル） |

### まだ入れていないもの

### 道具とアドインの関係

道具（Python）が鍛える側、アドイン（VBA）が回す側です。依頼が来ると、道具の入口は、開いているブックやアドインの中の
「表の整理」モジュールを読み、マクロの頭に書いてある「依頼の語」に当たるものを、AI より先に撃ちます。
アドインだけでも、マクロは一覧から人の手で撃てます。

## 動く条件

- Windows 版の Excel（デスクトップ版）
- Python 3.10 以降（`py` コマンド）と `pip install -r requirements.txt`
- Excel のトラストセンターで「VBA プロジェクト オブジェクト モデルへのアクセスを信頼する」を有効にする
- **手を動かす AI**。この道具は AI の手であって、AI そのものではありません。Claude Code や Antigravity のように、MCP で道具につなげる AI を
  別に用意してください。**API キーは要りません。** つないだ AI 自身が頭になります。依頼文を渡して最後まで回す命令（agent）や鍛える回路も、
  既定では道具が裏で Claude Code（`claude -p`）を呼ぶので、鍵は要りません。Gemini / Claude の API を直接使う道も残してありますが、使いたい方だけの選択肢です。
- AI がいなくても、道具の本体（マクロの取得・置換・シートの読み書き）は、人がコマンドを一行ずつ撃てば動きます（`py vba_manager.py list` など）。
  アドイン（秀コンボ.xlsm）は、Excel だけで動きます

よその方のパソコンでは、まだ動かしていません。確かめたのは、作者の一台（Python 3.14）で動かしてきたことと、このリポジトリの中身を別の場所に展開して、
そこから MCP サーバーが立ち上がることまでです。

## MCP サーバーとして登録する

Claude Code:

```powershell
claude mcp add excel-manager --scope user -- py "<このフォルダの絶対パス>\作業ファイル\project\python_scripts\vba_mcp_server.py"
```

Antigravity（`%USERPROFILE%\.gemini\antigravity-ide\mcp_config.json`）:

```json
{
  "mcpServers": {
    "excel-manager": {
      "command": "<python.exe の絶対パス>",
      "args": ["<このフォルダの絶対パス>/作業ファイル/project/python_scripts/vba_mcp_server.py"]
    }
  }
}
```

対象は常に「今アクティブに開いている Excel ブック」です。特定のブックやパスには依存しません。

## 名前について

ファイル名（`vba_manager.py`）や道具の名前（`vba("…")`）には、前身の名前が残っています。中身を先に出すことを優先しました。
