# 「表の整理」のマクロを鍛える手順

2026-09-19 夜。「表の整理」に足すマクロは、この手順でしか作らない。会話している AI が Gemini でも Claude でも同じ。

公開版（GitHub）には、作った表（xlsx）は入っていない。各フォルダで `py make_pairs.py` を撃つと作れる（見せていない表は `py make_pairs.py --unseen <種>`）。

## 1. 役割の分け方（いちばん大事）

| 役 | 担当 | 中身 |
|---|---|---|
| お題と依頼文を作る | 会話している AI（あなた） | `make_pairs.py` で「前」と「正解」の表を Python で作る。依頼文 `request.txt` と人の言い方 `phrases.txt` も書く |
| マクロを書く | 道具が呼ぶ AI（既定は Claude Code の Opus）か、会話している AI（あなた） | 既定は `forge_job.py` の中で自動で呼ばれる。あなたが書くなら 6 の `--prompt`／`--answer` を通す（**自分で書いて自分で見て合格にしない**） |
| 採点する | 道具（`python_scripts\vbam_forge.py`） | 表の写しでマクロを撃ち、正解の表と**全セルの値と型（数・日付・文字）**を突き合わせる。外れは書く AI に自動で返し、合うまで往復する |
| 登録する | 道具（`register_all.py`） | 台帳（`python_scripts\_agent_forge.json`）から「表の整理」モジュールを組み直す。頭の行（依頼の語・扱う・形）も道具が書く |

**合格と言ってよいのは、道具が `FORGE_RESULT <仕事の名前> passed` を出し、見せていない表（unseen_sweep）でも外れ 0 だったときだけ。**
sheet-info の範囲や結合の数が正解と同じだった、read-range で見た数セルが正しかった、は合格ではない。

## 2. 手順（1 本分）

作業の場所は `作業ファイル\project\fixtures`。Python は `py` で撃つ（`python` は入っていない）。

1. **お題を作る**: `fixtures\<フォルダ>\make_pairs.py`
   - 手本は `fixtures\差し込み\make_pairs.py`。見出しの語は `vocab.py`、元の表は `detail.py`（明細）・`shukei.py`（集計表）で作れる
   - 組は**本番＋試験 8 組以上**。ファイル名は `<名前>_本番_前.xlsx`／`<名前>_本番_正解.xlsx`、`<名前>_試験A_前.xlsx`／`<名前>_試験A_正解.xlsx` …
   - **組ごとに変えるもの**（変えなかった所は、マクロが決め打ちしても見抜けない）:
     - 見出しの語・シート名
     - 表の始まりの位置（A1・B3・上に表題の行がある）
     - **列の数と並び**
     - 件数（1 件・多件）
     - 日付の書き方（yyyy/m/d・和暦・m月d日）
     - その仕事に要らない列を抜いた表（例: 日付や金額の列が無い名簿。全部の組にある列は、マクロが「その列が無いと動かない」作りでも見抜けない）
     - 合計の行・途中の空行
     - **人の値がある表**（消えたら外れ）。マクロが書く列の中（帳票の下など）にも置く。書く所から離れた所にだけ置いても試しにならない
     - **2 回撃つ表**（本番の正解をそのまま「前」に写した組）
   - 正解は Python で組む（マクロを撃って正解を作らない）。COM で日付を書くときはシリアル値で書く（datetime を渡すと時差で前日になる）
   - `py make_pairs.py --unseen <種>` で見せていない表を作れるようにする（手本の `unseen(seed)`）
   - `REQUEST`（依頼文）に正解の決まりを全部書く。**列を意味（番号・団体・代表者…）で決める仕事は、どの表でも動く形にならない。**
     列は並びと形（文字の列・数の列・日付の列・左端／右端）で決まるように書く
   - `PHRASES`（人の言い方）は 6 本。登録済みの仕事（「一覧からひな形を差し込む」「様式に転記する」「帳票を一覧に直す」など）と
     同じ言い方にならないようにする
2. `py make_pairs.py`
3. `py -u forge_job.py <フォルダ> <仕事の名前> --turns 6`
   - 最後の行が `FORGE_RESULT <仕事の名前> passed` になるまで回す。`failed` なら道具が出した外れを読み、**まずお題（正解の表）を疑い**、
     次に依頼文に決まりを書き足して `--continue` で続ける
   - 2 本同時に回さない（台帳を両方が書く。錠があるので 2 本目は待たされる）
4. `unseen_sweep.py` の `JOBS` に `('<仕事の名前>', '<フォルダ>')` を足す → `py unseen_sweep.py <新しい種> <仕事の名前>` → 外れ 0
5. `py check_heads.py --fix`（表の語を書き込んでいないかの検査。違反 0 まで）
6. 秀コンボ.xlsm を開いた状態で `py register_all.py --write` → MCP の `vba("run-macro アドインの更新登録 --raw")`
7. `py check_phrases.py`（人の言い方で、そのマクロだけが撃たれるか。外れ 0）→ `py check_shape_fit.py`（撃てなくなる組 0）
8. 道具の `.py` を直したときだけ: `秀 20260113` の直下で `py sync_tools.py --from proj`（両側の pytest まで回る）

報告には数字を並べる: 往復の数、試した表の枚数、見せていない表の枚数と外れ、check_phrases の結果。

## 3. やってはいけないこと

- 自分でマクロを書いて `add-procedure`／`replace-procedure` で「表の整理」に入れる（台帳に載らず、check_heads・check_phrases・unseen_sweep の見張りの外になる）
- 頭の行（`' 依頼の語:`／`' 扱う:`／`' 形:`）を自分で書く。`' 形:` は道具が表から導く。`' 形: なし` はどの表にも撃たれる入口になる
- 目で見て合格にする
- 文字にして比べる（`str(実) == str(正解)` だと `0001` と `1` の違いも、数と文字の違いも見逃す。道具は型まで比べる）
- 道具の出力を見ずに「手順どおり」「合格」と報告する

## 6. 回路の中でマクロを書く AI

- `forge_job.py` をそのまま撃つと、マクロを書くのは道具が呼ぶ Claude Code（Opus）。Claude が鍛えたときも同じだった
- **会話している AI（あなた）が自分で書くときは `--prompt` と `--answer` を使う**（2026-09-19 から・API の鍵は要らない）。
  採点は今までどおり道具がする。書き手が変わるだけで、合格の物差しは同じ
  1. `py -u forge_job.py <フォルダ> <仕事の名前> --prompt`（前の続きなら `--continue`、お題を作り直したなら `--refresh` も付ける）
     → `<フォルダ>\_forge_prompt.txt` に問い（決まり・依頼・前と後の表・別の表・前回の外れ）が書かれる
  2. 問いを全部読み、マクロ（Sub 全文だけ・説明の文は付けない）を `<フォルダ>\_forge_answer.txt` に書く（UTF-8 でよい）
  3. `py -u forge_job.py <フォルダ> <仕事の名前> --answer` → 1 往復ぶん採点される。
     `FORGE_RESULT … passed` なら 2 の手順 4 へ。`failed` なら `_forge_prompt.txt` が次の問い（外れの説明と前回のマクロつき）に
     書き換わっている＝読み直して 2 へ戻る。外れが増えた答えは道具が捨て、いちばん良かった版から直させる
  - 同じ外れが 2 回続いたら、答えではなくお題か依頼文を疑う（道具は往復をまたいだくり返しを止めない＝止めるのはあなた）
- Gemini の API で書かせる口（`agent --forge … --ai gemini`）もあるが、Gemini の API キーが要る（2026-09-19 時点では入っていない）
